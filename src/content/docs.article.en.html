A shared session lets several people, and any agents they invite, edit the same buffers at once. Everyone keeps their own cursor, selection and undo history; edits travel peer to peer and merge without a central server.

Note

This page is sample content for gridline-style. Orbitline and its orbit command are fictional.

Before you start#

Sessions need Orbitline 0.9 or later on every machine. A session is tied to a folder, so open the project you want to share first. The status bar shows the session state:

offline live merged needs review

Start a session#

  1. Open the command palette with ⌘ K and run session: start, or use the command line below.

  2. Name the session after the work, not the person. The name appears in every collaborator’s window.

  3. Share the link the editor copies to your clipboard. Anyone with the link can ask to join; you approve each request.

Invite people and agents#

An agent joins a session exactly like a person: it gets a cursor, its edits are attributed to it, and it can be removed at any time. Roles decide what each participant may do.

RoleCan editCan inviteTypical use
OwnerYesYesStarted the session
EditorYesNoPairing teammates, agents
ViewerNoNoReviewers, demos

How merging works#

Every buffer is a CRDT. A local edit is applied immediately, then sent to peers, who integrate it by identifier rather than by position; every replica converges on the same text.

The engineering post A data model for multiplayer editing explains the trade-offs.

Review changes#

Changes from each participant stay attributable. Open Session › Review to read them as a diff grouped by author, then keep or revert each group.

Warning

Reverting a group also reverts later edits that depend on it. The review view marks those edits before you confirm.
